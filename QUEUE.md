# Автоматическая очередь Claude Code — «АкроБатя»

Очередь выполняет `docs/plan.md` сессию за сессией без участия человека. Каждая сессия плана — отдельный
запуск Claude Code с чистым контекстом; связь между запусками держат `CLAUDE.md`, `docs/map.md`,
`docs/progress.md`, отметки в плане и история Git. Схема перенесена из очереди «Мастерской» (`bny-studio`)
по эталону 10.6: без Docker и Postgres, под C++ (CMake, Ninja, MSVC), с лимитом по часам сброса.

## Как это устроено

```text
run-queue.ps1 ──► страж старта: этап 0 закрыт? (все пункты [x] и "verified": ["0"] в .queue/state.json)
      │          находит первую сессию с «- [ ]» (или непройденный рубеж), пишет её пачку в .queue/current.md
      ▼
claude -p "/next-task" --model claude-opus-5-5 --effort xhigh --dangerously-skip-permissions
      │          навык собирает контекст один раз и делает пункты по очереди: тесты и код (субагенты;
      │          workflow — только при -Effort ultracode), сборка своей цели под замком, коммит и отметка [x] — и так каждый пункт;
      │          в конце — tools/verify.py, снимки сцен, CHANGELOG, запись в журнал
      │          и ответ QUEUE: DONE / PARTIAL / NEEDS_HUMAN / BLOCKED
      ▼
run-queue.ps1 ──► считает отметки: все — сессия закрыта, часть — остаток уходит следующей сессии,
                 ноль — повтор, BLOCKED — остановка; лимит — запасная модель или ожидание сброса
```

После этапов 2, 4, 6, 8 и 9 идут **рубежи** Р1–Р5: полные проверки Debug и Release, ASan, фаззер, bench,
все снимки сцен, окно на экране на 8 секунд, скрипт `tools/verify_r<N>.py`, установщик и тихая установка,
запись в журнал. Рубежи закрывают контрольные точки M1–M5 эталона 9.6 на фикстурах; живая часть — в
«Нужна ручная проверка» `docs/progress.md`.

**Этап 0** очередь не выполняет: его делает Claude в интерактивной сессии с человеком (эталон 8.1). Пока в нём
есть хотя бы один пункт не `[x]` или в `.queue/state.json` нет `"verified": ["0"]`, `run-queue.ps1` (кроме
`-Status` и `-Setup`, **и с `-DryRun` тоже**) отказывается стартовать и печатает, что осталось: иначе
`Get-NextUnit` принял бы пункты этапа 0 за задания. `-Setup` пункты не отмечает — он проверяет окружение и
пишет `"verified": ["0"]` только когда все пункты уже `[x]` (в образце он ставил `[x]` сам, и страж обходился).

## Модель и усилие

**Opus 5.5 с усилием `xhigh`** во всех сессиях и рубежах (решение человека 23.10.2026; до него было `ultracode`) — это значения по умолчанию
`run-queue.ps1` (`-Model claude-opus-5-5 -Effort xhigh -VerifyEffort xhigh`). В заголовках сессий плана,
как в образце, стоит «усилие xhigh» — совпадает с флагами (при расхождении главнее флаги); взять усилие из заголовка можно ключом
`-UsePlanEffort`. Число ходов берётся из заголовка (`ходов 300`), если не задано `-MaxTurns`/`-VerifyMaxTurns`.
Сессия буксует — человек поднимает ходы в её строке.

Запасная модель — **Fable 5.1 с усилием `xhigh`** (`-FallbackModel claude-fable-5-1 -FallbackEffort xhigh`;
на время вызова, как и для основной, `CLAUDE_CODE_EFFORT_LEVEL=xhigh`; отдельный ключ нужен, если основную запустить с
`-Effort ultracode` — его Fable CLI может отвергнуть). На время каждого вызова очередь ставит `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=7200000`
(workflow и фоновые агенты досчитываются до 2 часов после хода) и `DISABLE_AUTOUPDATER=1`.

## Лимиты

Признак лимита (`Test-Limited`) — `api_error_status: 429` в JSON или в тексте ответа одно из: `usage limit`,
`usage credits`, `out of usage`, `rate limit`, `429`, `limit reached`, `resets at`, `switch to another model`,
`session limit`, `weekly limit`, `hit your … limit`, `resets [at|in] <цифра>`. Порядок при лимите (если сессия
ещё не отметила ни одного пункта):

1. лимит у основной модели → **та же сессия** на запасной (Fable 5.1, `xhigh`);
2. лимит и у запасной → разобрать «resets …» из ответа (`Get-ResetWaitSeconds`: `resets 9:30am`, `resets 14:05`,
   `resets at 02:10`, `resets in 25 min`, `resets in 2 hours`, `weekly limit · resets Oct 25, 9am`, старое
   `usage limit reached|<секунды Unix>`; прошедшее
   сегодня время — завтра; недельный с датой — не дальше 8 суток), ждать **до сброса плюс 2 минуты** по часам
   (сон ноутбука ожидание не растягивает); не разобралось — `-LimitWaitMinutes` (20);
3. после ожидания — **снова основная модель с её усилием (`xhigh`) на той же сессии**. Если время сброса основной было
   известно и наступило раньше — очередь возвращается к ней, не дожидаясь лимита запасной.

Перегрузка сервера (529) — пауза 2–15 минут. Ошибка API в конце сессии, которая уже отметила пункты, — не повод
ждать: сделанное считается как обычно. Проверка всего этого без настоящего `claude` —
`.\run-queue.ps1 -SimulateLimit` (заглушка отвечает лимитом два раза, ожидание не спит, вызовы пишутся в
`.queue\simulate-limit.jsonl`); её гоняет `tools/test_reset_parse.ps1` на временной копии репозитория.

## Первый запуск

Этап 0 закрывают человек и Claude интерактивно (пункты отмечаются `[x]` вручную по мере выполнения). Затем:

```powershell
powershell -ExecutionPolicy Bypass -File .\run-queue.ps1 -Setup    # проверка окружения; "verified": ["0"] — только при всех [x]
powershell -ExecutionPolicy Bypass -File .\run-queue.ps1 -DryRun   # должно показать «Этап 1 · Сессия 1.1 · …»
claude        # один раз войти в аккаунт, затем /exit
powershell -ExecutionPolicy Bypass -File .\run-queue.ps1           # очередь
```

`-Setup` ничего не ставит: проверяет `cl` и `clang-format --version` (19.1.5) через `tools\vcenv.cmd`,
`C:\Qt\6.12.0`, `C:\src\mupdf\platform\win32\x64\Debug\libmupdf.lib` (и Release), vcpkg, `C:\Tools\{qpdf,pdfcpu,tessdata,venv-test}`,
`py -3.14`, `OTTISK_PYTHON` (импорт пакетов venv), `claude`, `git`, `node`; копирует `claude-setup\` в `.claude\`,
создаёт `.claude\settings.local.json`, если его нет; при всех `[x]` прогоняет `py -3.14 tools\verify.py`
(`-SkipVerify` — без него) и пишет `"verified": ["0"]`.

## Управление

| Что нужно | Команда |
|---|---|
| Прогресс по этапам и следующее задание | `.\run-queue.ps1 -Status` |
| Посмотреть следующее задание, ничего не запуская | `.\run-queue.ps1 -DryRun` (пишет `.queue\current.md`) |
| Выполнить не больше N заданий | `.\run-queue.ps1 -MaxTasks 3` |
| Другая модель или усилие | `-Model … -Effort … -VerifyEffort …`, запасная — `-FallbackModel … -FallbackEffort …` |
| Больше ходов | `-MaxTurns 350 -VerifyMaxTurns 320` (или правка строки сессии) |
| Остановить после текущего задания | создать пустой файл `.queue\STOP` |
| Остановить сразу | `Ctrl+C` (незавершённая работа останется в папке; следующая сессия её продолжит) |
| Продолжить | просто запустить скрипт снова |
| Повторить сессию | заменить `[x]` на `[ ]` у её пунктов в `docs/plan.md` |
| Повторить рубеж | убрать его номер (`Р2`) из `verified` в `.queue\state.json` |
| Поменять состав сессии | править строку `### Сессия …` и порядок пунктов под ней (между сессиями) |
| Выполнить одно задание вручную | в Claude Code из корня: `/next-task` |
| После пилота | замечания — в `docs/pilot.md` строками `- [ ] дата · кто · что`, у пунктов 10.1 `[~]` → `[ ]`, запустить скрипт |

Коды выхода: 0 — план выполнен, `-MaxTasks` или `STOP`; 1 — отказ старта (этап 0) или `-Setup` не прошёл;
2 — `QUEUE: BLOCKED`; 3 — задание не удалось после `-Retries + 1` попыток подряд.

## Как наблюдать

* Консоль: строка на задание — этап, сессия, модель и усилие, ходы; итог и время.
* `.queue\log\summary.log` — одна строка на задание: итог, ключ (`task|2|2.4b`, `verify|Р1`), модель/усилие, минуты,
  ходы, стоимость, сколько пунктов закрыто; строки `LIMIT` и `OVERLOAD`. Файлы `.queue` — UTF-8 без BOM: в
  Windows PowerShell 5.1 читать `Get-Content -Encoding UTF8 -Tail 20 .queue\log\summary.log`, иначе кириллица — кракозябры.
* `.queue\log\<время>-task-sN.json` / `-verify-sN.json` — полный ответ Claude Code.
* `.queue\current.md` — что сейчас делается; `.queue\workflows.log` — запущенные workflow (продолжить оборванный —
  `Workflow({scriptPath, resumeFromRunId})`).
* `.queue\build.lock` — кто сейчас собирает; `build\debug\build.log` — последняя сборка.
* `.queue\screenshots\` — снимки сцен; `.queue\r<N>\` — артефакты рубежей.
* `git log --oneline` — история по пунктам; `docs\progress.md` — журнал и ручные проверки.

## Почему после этапа 10 нет рубежа Р6

Сессия 10.1 до пилота помечена `[~]` целиком (её открывает человек после двух недель пилота). `Get-NextUnit`
пропускает блок, у которого нет пунктов `[ ]`, — поэтому рубеж после этапа 10 запустился бы **сразу после Р5, до
пилота**, и проверял бы несделанное. Регресс Р1–Р5 на сборке 1.0.0 делает сама 10.1 (`tools/verify_r5.py`). До
пилота `-Status` показывает этап 10 закрытым («3/3 … ручных: 3») — это ожидание, а не ошибка; после снятия `[~]`
строка станет 0/3, и очередь возьмёт 10.1.

## Суффикс-буквы в номерах сессий

2.2b, 2.4b, 2.5b, 8.1b — сессии, выделенные из перегруженных 2.2, 2.4, 2.5 и 8.1. Это допустимо:
`Read-BlockHeader` берёт id как `\S+`, ключи `task|2|2.4b` уникальны, порядок — порядок файла. Нумерацию
**не «исправлять»**: на неё ссылаются заметки других сессий и `docs/sessions.md`.

## Что происходит при сбоях

* **Этап 0 не закрыт.** Скрипт печатает оставшиеся пункты и что сделать; код 1.
* **Лимит использования.** Запасная модель → ожидание сброса → основная (раздел «Лимиты»).
* **Сделана часть пунктов** (`QUEUE: PARTIAL` или кончились ходы). Не неудача: отмеченное остаётся, страховочный
  коммит, следующая сессия берёт остаток.
* **Не сделано ни одного пункта.** Страховочный коммит и повтор; после `-Retries + 1` попыток подряд без отметок
  очередь останавливается (код 3). Перед перезапуском обнулить `failCount` и `lastKey` в `.queue\state.json`.
* **`QUEUE: BLOCKED`.** Claude решил, что дальше без человека нельзя (чаще среда: `cl` не найден, диск, `C:\Tools`;
  новая зависимость; противоречие в документах). Очередь останавливается (код 2); причина — в консоли,
  `.queue\log\summary.log` и `docs\progress.md`.
* **`QUEUE: NEEDS_HUMAN`.** Результат пункта без человека невозможен (как 10.1): пункт `[~]`, очередь идёт дальше.
  Живые проверки сделанного — не `[~]`, а строки «Нужна ручная проверка».

## Безопасность

Очередь работает с флагом `--dangerously-skip-permissions`: Claude Code выполняет команды без подтверждения.
Что ограничивает риск:

* защитный хук `guard.ps1` и запреты `.claude/settings.json` действуют и в этом режиме (проверяет
  `tools/test_guard.ps1`); хук видит командную строку — то, что программа пишет внутри себя, он не видит;
  команда хука находит `guard.ps1` через `CLAUDE_PROJECT_DIR` (работает из любого каталога сессии) и явно
  возвращает его код: `powershell -Command` сам превратил бы запрет (2) в 1, а 1 Claude Code считает
  нестрашной ошибкой хука и команду пропускает;
* `C:\Qt`, `C:\src\mupdf`, `C:\Tools` (с `vcpkg` и корпусом `ottisk\corpus`) — только чтение (кроме `C:\Tools\logs`);
  установщики системы (VS Installer, `vs_*.exe`, `msiexec /i|/x`, `winget --scope machine`, `vc_redist /install`)
  запрещены; наш `dist\AcroBatya-*-setup.exe /VERYSILENT` и `unins000.exe /VERYSILENT` — разрешены;
* всё под Git, каждый пункт — отдельный коммит, откат — `git revert`; удалённого репозитория нет, `git push` запрещён;
* у очереди нет настоящих сертификатов, сети в тестах, данных человека: `OTTISK_INSTANCE=test`, `OTTISK_DATA_DIR`
  в `build`.

## Чего очередь не сделает сама

Этап 0; три вопроса объёма (эталон 12); LibreOffice с UAC; Acrobat Reader; живую подпись сертификатом из хранилища
и с меткой DigiCert; сканер и принтер; установку на чистую учётную запись, SmartScreen и «приложение по умолчанию»;
пилот и выпуск 1.0.0 до пилота. Всё это — список вверху `docs/progress.md`.
