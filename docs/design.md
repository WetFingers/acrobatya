## 0. Коротко

**Что это.** Программа для Windows 10/11, которая открывает, показывает, печатает, комментирует, редактирует текст и картинки «на месте», собирает и разбирает по страницам, защищает паролем, подписывает сертификатом (настоящий PAdES) и проверяет чужие подписи, заполняет и создаёт формы, распознаёт сканы и конвертирует Office ↔ PDF. Объём — уровень Adobe Acrobat Standard; Pro и облако — нет. Для себя и семьи, не продаётся — поэтому движок MuPDF под AGPL допустим.

**Главные решения эталона сверх решений человека.** Порядок этапов — риск-первым (ядро → просмотрщик с печатью → редактор текста → подписи → комментарии → формы → страницы/конвертация/оформление/защита → OCR/сканер/доступность → оболочка/английский/выпуск); все цели собираются с `/MD`, MuPDF Debug пересобирается с `MultiThreadedDLL`; раскладка окна и панель «Все инструменты» — как в новом Acrobat, из `ToolRegistry` с первого рубежа; все каталоги данных программы — ASCII (`%LOCALAPPDATA%\AcroBatya\`); сертификатное шифрование (security-11) — после 1.0; покрытие объёма считается из ctest макросом `OT_FEATURE("id")`.

**Что человек получит в конце.** `dist/AcroBatya-0.9.0-setup.exe` (per-user, без администратора), затем — после двух недель пилота — `AcroBatya-1.0.0-setup.exe`. По дороге — пять рубежей с установщиком (Р1 — читалка с печатью, Р2 — редактор текста и подписи, Р3 — комментарии и формы, Р4 — весь объём Standard, Р5 — выпуск 0.9.0) и контрольные точки M1–M5 (§9.6).

## 1. Назначение и объём

### 1.1 Что это и для кого

Настольный PDF-редактор для одной семьи: открыть и прочитать, пометить и отправить, заполнить и подписать, собрать из сканов, защитить, перевести в Word и обратно, исправить опечатку. Один компьютер (Windows 11, i7-13650HX, 15,7 ГБ ОЗУ), без аккаунтов, телеметрии и сервера. Уровень возможностей — Acrobat Standard; раскладка, названия инструментов и горячие клавиши — как в Acrobat, чтобы человек, привыкший к Acrobat, узнал программу с первой минуты. Файлы, которые делает «АкроБатя», обязаны открываться в Acrobat Reader и Edge без предупреждений и ремонта.

### 1.2 Правило отбора и числа

Из 469 функций каталога берутся все **Reader и Standard** с важностью **core и important** — 224 ID (48 + 76 Reader, 44 + 56 Standard). ## 2. Сценарии использования

Сценарии — основа сквозных тестов `tests/e2e/scenarios_test.cpp` (через `core`/`services` без UI, §9.1) и ручных проверок рубежей (§9.7). Каждый назван коротко; в тестах имена те же.

1. **Открыть и прочитать.** Двойной щелчок по `договор.pdf` в Проводнике → вкладка в уже открытом окне (второй экземпляр передаёт файл первому), первая страница видна ≤ 300 мс, листание колесом без швов; `Ctrl+F` «пункт 4.2» → подсветка и панель результатов; `Ctrl+H` — режим чтения. Закрыть — ничего не спрашивает: правок не было.
2. **Пометить и отправить.** Выделить фразу → «Выделить текст» жёлтым → записка с ответом → «Поделиться → Отправить по почте» открывает письмо Outlook/почтового клиента по MAPI с вложением. Получатель с Acrobat Reader видит пометки и ответы в панели комментариев.
3. **Заполнить форму и подписать визуально.** Открыть анкету с полями → фиолетовая полоса «Документ содержит поля» → `Tab` по полям, флажки, список → «Заполнить и подписать → Подпись → Нарисовать» → подпись сохранена для следующего раза → `Ctrl+S` инкрементально. В Reader форма остаётся заполняемой, подпись — штамп с картинкой.
4. **Подписать сертификатом.** «Использовать сертификат → Поставить цифровую подпись» → рамка на странице → выбор удостоверения (файл `.pfx` или диалог хранилища Windows) → причина, внешний вид → подпись B-T с меткой времени DigiCert → синяя полоса «Подписано, все подписи действительны». В Acrobat Reader — зелёная галочка и «LTV включено» после «Добавить сведения для проверки».
5. **Проверить чужую подпись.** Открыть подписанный чужой файл → панель «Подписи»: статус (действительна / неизвестный подписант / изменён после подписи), сертификат, цепочка, отзыв, метка времени; «Просмотреть подписанную версию» открывает ревизию в новой вкладке «только чтение».
6. **Объединить сканы.** «Создать → Объединить файлы» → три PDF и две JPEG → порядок перетаскиванием → «Объединить» → новая вкладка «Без имени» (операция с перезаписью, без undo) → «Упорядочить страницы»: повернуть две, удалить пустую → «Уменьшить размер» → «Сохранить как».
7. **Вытащить страницы.** В «Упорядочить страницы» выделить 3–5 → «Извлечь → в отдельный файл, удалить из исходного» → закладки и ссылки на удалённые страницы вычищены; `Ctrl+Z` возвращает страницы.
8. **Защитить паролем.** «Защитить → Защитить паролем → Редактирование» → пароль с индикатором надёжности → AES-256 R6, права «печать разрешена, копирование запрещено» → «Сохранить как» (полная запись). В Reader файл открывается с паролем, копирование серое.
9. **Office → PDF.** «Создать → Из файла» `отчёт.docx` → LibreOffice headless (установлен человеком) → PDF с картинками и тегами во вкладке; если LibreOffice нет — плашка «Установите LibreOffice или укажите `soffice.com` в настройках»; для `.docx` при наличии Word — путь через Word COM.
10. **PDF → Word.** «Экспорт PDF → Word (.docx)» → Word COM в отдельном STA-потоке с таймаутом → файл рядом; XLSX/PPTX в списке серые с подсказкой «недоступно».
11. **Править опечатку.** «Редактировать PDF» → клик по абзацу → рамка блока → исправить слово → перевёрстка абзаца → остальная страница не изменилась байт в байт; шрифт без нужного глифа → честное «шрифт подменён на …». В Reader текст выделяется и ищется.
12. **Распознать скан.** Открыть `скан.pdf` → полоса «Похоже на скан — распознать текст?» → «Распознать» (rus+eng, Searchable Image) → невидимый слой текста, поиск и копирование работают; «Исправить распознанный текст» показывает слова с низкой уверенностью.
13. **Отсканировать.** «Сканировать → со сканера» (WIA: dpi, цвет, ADF, дуплекс) → «Ещё страницы?» → «Улучшить скан» (deskew, фон, резкость) → «Распознать» → сохранить.
14. **Сделать форму из плоской анкеты.** «Подготовить форму → Автоопределение» → поля по подчёркиваниям и рамкам → поправить имена и добавить поле «Итого» с вычислением суммы → «Предпросмотр» → в Reader форма заполняется и сумма считается.
15. **Напечатать буклет.** `Ctrl+P` → «Буклет», обе стороны, предпросмотр → на принтере или в «Microsoft Print to PDF» → страницы спущены парами по формуле буклета; `/p` и `/pt` из контекстного меню Проводника печатают молча.

## 3. Функции по модулям

Для каждого модуля: поведение, диалоги, клавиши (полная таблица — §6.8), граничные случаи, совместимость с Acrobat. Код модуля живёт в `src/core/<модуль>/` (без Qt) и `src/ui/tools/<инструмент>/` (класс `*Tool`, §5.2). Что обязано открываться в Acrobat Reader без предупреждений: всё, что пишется на диск; косвенный критерий — `qpdf --check` = 0 ∧ `pdfcpu validate -m strict` = 0 ∧ `mutool clean` без «repairing» ∧ pypdfium2 рендерит (§9.4).

### 3.1 Просмотр и навигация (view-01…13, 15, 17, 18, 21, 22, 25–27, 30–33, 36, 45–47, 50, 51; pro-45, 47)

- **Открытие.** `Ctrl+O`, перетаскивание в окно, аргумент командной строки, ProgID из Проводника; второй экземпляр передаёт файлы первому через `QLocalSocket` (имя `AcroBatya-<sid>`; в тестах и очереди — с суффиксом `OTTISK_INSTANCE`). Не-PDF (XPS, EPUB, CBZ, PNG/JPEG/TIFF, TXT, HTML) открываются тем же `fz_open_document` в режиме «только просмотр + Сохранить как PDF». Пароль — диалог с тремя попытками, флажок «запомнить на время сессии». Восстановленный файл (`pdf_was_repaired`) — жёлтая полоса «Файл восстановлен, сохранение будет полным».
- **Раскладка страниц:** одна, непрерывно, разворот, разворот непрерывно, титул отдельно (`/PageLayout` из файла уважается при открытии, если в настройках «как в документе»); поворот вида (`Ctrl+Shift+=`/`-`) — матрица раскладки, документ не меняется; зазор 8 px; серый холст.
- **Масштаб:** 8–6400 %, `Ctrl+колесо` вокруг курсора, `Ctrl+0/1/2/3` (страница/реальный/ширина/видимое), поле ввода в строке состояния с предустановками, «Лупа» (панель 200–800 %), «Панорамирование и масштаб» (панель с миниатюрой и рамкой), масштаб рамкой (`Z`), цикл зума (`Shift+Z`). Реальный размер — по DPI монитора.
- **Навигация:** страница (`Ctrl+Shift+N`, поле ввода с логическими номерами `/PageLabels` — ввод «iv» или «3»), `Home/End/PgUp/PgDn`, история видов `Alt+←/→` (стек из 50 видов: страница, масштаб, прокрутка), ссылки (внутренние — переход, `/GoToR` — спросить и открыть файл, `/URI` — подтверждение §7.4, `/Launch` — запрещено), закладки (панель с деревом, цвет/стиль `fz_outline_item.flags`, авто-раскрытие по `/PageMode`), миниатюры (панель, рендер видимых 160 px, перетаскивание в «Упорядочить»), слои (`/OCProperties`: включить/выключить, вложенность, «Сбросить к исходному»; печать и экспорт уважают `/Print` и `/View`), вложения (панель: открыть, сохранить, добавить, описание; `/EmbeddedFiles` и `/FileAttachment`), назначения (панель `/Dests`: список, переход, переименование — view-50).
- **Режимы:** чтение (`Ctrl+H`: только холст и тонкая полоса внизу), полный экран (`Ctrl+L`: без рамки на текущем мониторе, настройки переходов и автопродвижения, `Esc`), ночной/замена цветов (`recolor_device`, §3.16), «Крупные элементы» (ocr-42).
- **Свойства документа** (`Ctrl+D`): Описание (`/Info` + XMP Dublin Core — редактируется), Защита (права `/P`, метод шифрования, «Изменить…»), Шрифты (обход ресурсов всех страниц: имя, тип, встроен/подмножество/подменён, кодировка), Начальный вид (`/PageMode`, `/PageLayout`, `/OpenAction`, `/ViewerPreferences` — редактируется), Пользовательские (свои ключи `/Info`), Дополнительно (версия PDF, линеаризован, теги, PDF/A-заявление, размер, число объектов, `pdf_check_document` предупреждения).
- **PDF/A (pro-45):** файл с `pdfaid:part` в XMP открывается «только для чтения» с синей полосой «Этот файл заявляет PDF/A [Включить редактирование]» (настройка, как в Acrobat); overprint preview (pro-47) — флаг `fz_overprint`-симуляции у рендера по настройке «Всегда / Только для PDF/X / Никогда».
- **Сглаживание и качество (view-36):** AA 8 текст/линии/картинки, «тонкие линии», кеш страниц (§4.3), «показать Art/Trim/Bleed» рамками в оверлее, «использовать логические номера страниц», масштаб и раскладка по умолчанию.
- **Граничные случаи:** 1 200-страничный файл — раскладка знает только `fz_bound_page` × N (дёшево), страницы рендерятся лениво; страница 0×0 или 14 400 pt — ограничение раскладки 200 × 200 дюймов; повреждённые страницы — заглушка «Страница не отрисована» и запись в журнал, остальные живут; `/Rotate` не кратный 90 — округляется.
- **Acrobat:** клавиши и названия команд — Acrobat; `/ViewerPreferences` и `/OpenAction` уважаются; наши настройки не пишутся в файл.

### 3.2 Текст, поиск и выделение (view-10, 11, 19, 32; ocr-41)

- **Извлечение:** `fz_stext_page` с флагами `FZ_STEXT_PRESERVE_LIGATURES | PRESERVE_WHITESPACE | ACCURATE_BBOXES | PARAGRAPH_BREAK | SEGMENT`; кеш stext LRU 16 на документ; порядок чтения — блоки по `SEGMENT`, для тегированных файлов — порядок дерева структуры (§3.16).
- **Выделение** (`V`): по символам, строкам (столбцы — `Alt`+рамка), «Выделить всё» (`Ctrl+A`), копирование как текст и RTF-подобный HTML (`QMimeData`), «Снимок» (`X`: область → буфер как PNG при DPI монитора; `Alt` — при 300 dpi). Курсор I-beam над текстом, рука вне. Клавиатурный курсор выделения (ocr-41): `Shift+стрелки` с видимым курсором.
- **Поиск** (`Ctrl+F`): панель над документом: поле, «целое слово», «регистр», «регулярное выражение» (`fz_new_search`), счётчик «3 из 17», `F3`/`Shift+F3`, `Esc`; подсветка всех совпадений оверлеем; поиск идёт в потоке документа страницами с прогрессом и отменой; по умолчанию — по текущему документу, «Расширенный поиск» (`Ctrl+Shift+F`) — окно: все открытые документы или папка (рекурсивно, фильтр `*.pdf`), результаты деревом «файл → страница → контекст», двойной щелчок открывает; индекс папки — sqlite FTS5 в `%LOCALAPPDATA%\AcroBatya\state.sqlite` (таблица `fts_pages`, ключ = путь + mtime), без стемминга; «Включить вложения и закладки» — флажки.
- **Граничные случаи:** текст без пробелов в потоке (`PRESERVE_WHITESPACE` + эвристика по расстоянию), Type3 и вертикальный CJK — выделение по bbox, поиск по stext работает; скан без OCR — поиск даёт «нет текста — распознать?» с кнопкой (§3.15); лигатуры «ﬁ» ищутся как «fi».

### 3.3 Печать (view-37–43; `/p`, `/pt`)

- **Свой диалог** `Ctrl+P` с предпросмотром (первая страница результата, листание): принтер (`QPrinterInfo`, по умолчанию системный), «Свойства принтера…» открывает нативный `QPrintDialog` на том же `QPrinter` (лотки, качество драйвера — то, чего `QPageSetupDialog` не даёт), копии и подбор, страницы (все/текущая/диапазон «1-3, 7, 12-»/чётные/нечётные/обратный порядок/выделенные в «Упорядочить»), ориентация (авто/книжная/альбомная), «Размер и обработка»: вписать / реальный размер / уменьшить негабаритные / свой масштаб, **несколько на листе** (n-up 2×2 и др., порядок, рамки), **буклет** (обе стороны / только лицо / только оборот, корешок слева/справа, спуск полос формулой `(n, 1), (2, n−1), …` с добивкой до кратного 4), **постер** (масштаб, перекрытие, метки реза); «Комментарии и формы»: документ / документ и пометки / только поля; «Печать как изображение» (view-43), «Серый», дуплекс (длинная/короткая сторона), «Сводка комментариев» (приложить страницы сводки, §3.4).
- **Механика:** `QPrinter(HighResolution)` + `QPainter`; каждая страница растрируется MuPDF полосами ≤ 64 МБ при DPI принтера (`fz_run_display_list` со `scissor`; при 600 dpi A4 — 4 полосы) и рисуется `drawImage` в точные `QRectF`; аннотации — по режиму «Комментарии и формы» (`fz_run_page_contents` против `fz_run_page`); скрытые слои не печатаются (`/Print`); `imposition.h` (n-up/буклет/постер) чистая логика — тестируется без принтера; печать в файл — `QPrinter::PdfFormat` (суррогат в тестах: результат проверяется `qpdf --check` и эталонами раскладки) и через GDI `StartDoc` с `lpszOutput` для «Microsoft Print to PDF» без диалога порта.
- **Командная строка:** `AcroBatya.exe /p файл` — печать на принтер по умолчанию без окна; `/pt файл принтер драйвер порт` — на указанный; оба регистрируются в ProgID установщиком (`shell\print`, `shell\printto`); код выхода 0/1, ошибка — в журнал.
- **Граничные случаи:** страницы разных размеров в буклете — вписать по максимальной; принтер без дуплекса — буклет «только лицо» с подсказкой; 0 страниц в диапазоне — кнопка «Печать» серая; отмена — `fz_cookie.abort` и `QPrinter::abort()`.
- **Acrobat:** названия режимов и порядок вкладок — как в диалоге Acrobat; «Microsoft Print to PDF» заменяет Adobe PDF printer (create-15/16 — настройки печати в PDF живут в §3.18 «Настройки → Печать»).

### 3.4 Комментарии и аннотации (comment-01…14, 18–21, 24, 25, 27, 29, 30, 40–44)

- **Инструмент «Добавить комментарии»** (панель слева из `ToolRegistry`): Записка (`S`), Выделить (`U`) / Подчеркнуть / Зачеркнуть / Волнистая, Вставить текст / Заменить текст (каретка + `/StrikeOut` в группе), Текст (`J`, FreeText), Выноска (FreeText с `/CL`), Рисовать (`D`, Ink с толщиной/цветом/сглаживанием) и Ластик (по штрихам), Фигуры (`R` прямоугольник, эллипс, линия, стрелка, многоугольник, ломаная, облако — `/BE`), Штамп (`K`: палитра категорий Стандартные/Динамические/Подписи/Пользовательские, из буфера — comment-41, из файла PNG/JPEG/PDF), Вложить файл (`/FileAttachment` с иконкой), Измерить (§ниже), «закрепить инструмент» (comment-42, двойной щелчок или флажок).
- **Ядро:** 28 подтипов аннотаций читаются и рисуются (`pdf_annot`), создаются 14 (Text, Highlight, Underline, StrikeOut, Squiggly, Caret, FreeText, Ink, Square, Circle, Line, Polygon, PolyLine, Stamp, FileAttachment); внешний вид — синтез MuPDF (`pdf_update_appearance`) с нашими сеттерами (`pdf_set_annot_*`, `/DA` для FreeText с кириллицей через встроенный TrueType, `/BE` облако — свой AP), `/NM`, `/M`, `/CreationDate`, `/T` автор из «Identity», `/Subj`, `/C`/`/IC`, `/CA`, `/BS` (ширина, стиль, пунктир — `pdf_add_annot_border_dash_item`). `AnnotRef{page, objnum}` в UI, `pdf_annot*` не живёт дольше операции (§4.1). Каждая правка — операция журнала (undo/redo с именем «Отменить: записка»).

### 3.8 Подписи X.509 — PAdES (sign-05, 06, 08, 10–22, 25–28, 30–34; forms-17; security-09 часть)

- **Инструмент «Использовать сертификат»:** Поставить цифровую подпись (рамка на странице или невидимая), Сертифицировать (видимая/невидимая; разрешённые изменения: никакие / заполнение форм и подписи / + комментарии — DocMDP P=1/2/3), Метка времени документа (DocTimeStamp, sign-20), Проверить все подписи.
- **Диалог подписания:** удостоверение (список своих: `.pfx` из `%LOCALAPPDATA%\AcroBatya\ids\` с паролем через DPAPI по желанию; хранилище Windows — `CryptUIDlgSelectCertificateFromStore` на `MY`, фильтр «есть закрытый ключ и Digital Signature»; «Создать самоподписанное» — RSA-3072/ECDSA P-256 на 5 лет), причина/место/контакт (sign-14), внешний вид (конструктор: имя, дата, причина, логотип PNG, рукописная картинка из Fill & Sign, «только изображение», язык), «Заблокировать документ после подписи» (`/Lock` всех полей / `/Perms`), «Проверить документ» — предупреждения (sign-17: JavaScript, действия, вложения, внешние ссылки, динамический контент) с кнопкой «Просмотреть», метка времени (сервер из настроек, по умолчанию DigiCert, флажок «без метки, если сервер недоступен — спросить»), «Добавить сведения LTV после подписи» (B-LT, по умолчанию «спросить, если данных много»).
- **Механика (`core/sign`):** `pdf_create_signature_widget` или существующее поле `/Sig` → `AcroBatyaSigner : pdf_pkcs7_signer` (`max_digest_size` = 16 КиБ резерв `/Contents`), `create_digest` считает SHA-256 потока и собирает CMS: `CMS_sign(NULL, NULL, chain, NULL, CMS_DETACHED|CMS_BINARY|CMS_PARTIAL|CMS_NOSMIMECAP|CMS_CADES|CMS_NO_SIGNING_TIME)` + `CMS_add1_signer` с ESS `signing-certificate-v2` (SHA-256), `CMS_final`; затем TSA-токен (RFC 3161: `TS_REQ` с nonce и `certReq`, HTTP через `HttpFetcher`, ответ `TS_RESP_verify_token` по цепочке TSA) добавляется unsigned-атрибутом `id-aa-timeStampToken`; словарь `/V` патчится **до** записи: `/SubFilter` (`ETSI.CAdES.detached` по умолчанию, `adbe.pkcs7.detached` — настройка «совместимость»), `/Reason`, `/Location`, `/ContactInfo`, `/M`, `/Prop_Build`; каталог — `/Extensions /ESIC /BaseVersion /1.7 /ExtensionLevel 2` только для CAdES; запись — инкрементально (`pdf_sign_signature`-поток MuPDF с патчем `/ByteRange` и `/Contents`), сохранение в файл через `fz_output` на `_wfopen` (подпись считается по файлу, не по памяти — `fz_stream_from_output`).
- **CNG-путь (sign-08):** ключ из хранилища не экспортируется — `NCryptOpenKey` по `CERT_NCRYPT_KEY_SPEC`, хэш подписываемых атрибутов (`CMS_SignerInfo_sign` заменяется: атрибуты собираются OpenSSL, `NCryptSignHash` с `BCRYPT_PKCS1_PADDING_INFO`/`SHA256`, для ECDSA — P1363 → DER), подпись подставляется в `CMS_SignerInfo`; PIN-диалог показывает Windows. В тестах — `PFXImportCertStore(…, PKCS12_NO_PERSIST_KEY | PKCS12_ALWAYS_CNG_KSP)` без UI; сравнение атрибутов CNG-пути с OpenSSL-путём байт в байт.
- **Валидатор (`Verifier`):** для каждой подписи — `pdf_signature_contents` → `CMS_ContentInfo`; целостность: `CMS_verify(…, CMS_BINARY|CMS_NO_SIGNER_CERT_VERIFY|CMS_DETACHED)` по `/ByteRange` (без `CMS_CADES`); доверие: цепочка `X509_STORE` из нашего хранилища (`%LOCALAPPDATA%\AcroBatya\trust\` — свои якоря + кеш EUTL/AATL; корни Windows — опция, по умолчанию выкл., как `iMSStoreTrusted=0`), отзыв — OCSP (`OCSP_*`) затем CRL, из DSS-данных документа в первую очередь (LTV), затем сеть (если разрешена, §7.4); время — из метки времени подписи, иначе `/M` «заявленное»; метка — `TS_RESP_verify_token` + цепочка TSA; изменения после подписи — `pdf_validate_change_history` + свой анализ инкрементальных секций: разрешённые (заполнение полей, новые подписи, DSS, DocTimeStamp, комментарии при P=3) против запрещённых; DocMDP — `/Perms /DocMDP` с `/P`. **Статусы как в Acrobat:** «Действительна» (зелёная галочка), «Действительна, подписант не доверен» (жёлтый треугольник — целостность есть, доверия нет), «Неизвестно» (не удалось проверить отзыв/время), «Недействительна» (красный крест: документ изменён, подпись не совпадает, сертификат отозван на момент подписи), «Подписано и сертифицировано» (синяя лента); флаг «LTV включено». Полоса сообщений: синяя «Подписано, все подписи действительны [Панель подписей]» / жёлтая «Проблемы с подписью» / красная.
- **Панель «Подписи»** (справа): дерево «Подпись 1: Иванов И. (действительна)» → свойства (кто, когда, причина, место, метка времени, формат, уровень PAdES B-B/T/LT/LTA), сертификат (Сводка, Детали — все поля, Отзыв, Доверие — «доверять этому сертификату для подписей / сертификации», Политики), «Просмотреть подписанную версию» (байты `[0, end_of_range)` → временный файл → вкладка «только чтение»; «Сравнить с текущей» — sign-29, Pro, после 1.0 — в меню нет), «Добавить сведения для проверки» (DSS: `/DSS /Certs /OCSPs /CRLs` + `/VRI` по хэшу подписи — инкрементальная секция), «Очистить подпись» (sign-22), «Проверить все».
- **LTV и B-LTA (sign-19, 20, 21):** после подписи при «добавить LTV» — DSS; «Метка времени документа» — DocTimeStamp (`/Type /DocTimeStamp`, `/SubFilter /ETSI.RFC3161`) отдельной инкрементальной секцией, повторяемо (продление).
- **Доверие (sign-30–34):** диалог «Доверенные сертификаты» (импорт `.cer/.p7b/.fdf`, экспорт, «доверять для: подписей / сертификации / динамического контента / JS», удалить), EUTL — LOTL XML (`ETSI TS 119 612`) с проверкой подписи списка и загрузкой национальных списков (кеш, обновление раз в две недели через `TrustUpdater`), AATL — попытка разбора `tl12.acrobatsecuritysettings` (PDF с XML и base64-сертификатами) с честным отказом; «Серверы времени» (список URL, по умолчанию DigiCert, Sectigo, GlobalSign; «по умолчанию»; «проверить» делает тестовый запрос); «Удостоверения» (список, по умолчанию, экспорт сертификата, удалить, смена пароля `.pfx`).
- **Граничные случаи:** подпись без `/ByteRange` покрытия хвоста (`end_of_range < file size`) — «изменён после подписи» с анализом; несколько подписей и DocMDP + FieldMDP; сертификат с истёкшим сроком, но подпись с меткой до истечения — «действительна» (проверка на время метки); отозван после подписи — действительна; ECDSA и RSA-PSS (чтение) — поддерживаются, RSA-PSS на запись — нет; CMS без ESS — читаем; `adbe.pkcs7.sha1` (старые) — читаем, «устаревший алгоритм»; `adbe.x509.rsa_sha1` — «не поддерживается»; токен TSA 7,6 КБ (GlobalSign) влезает в 16 КиБ; сеть недоступна — статус «Неизвестно (нет данных об отзыве)», не «Недействительна».
- **Acrobat:** наши B-T/LT/LTA — зелёная галочка в Reader и «LTV включено»; сертифицированный документ P=2 — заполнение формы в Reader не ломает статус; `adbe.pkcs7.detached` для старых валидаторов — переключателем. ### 3.9 Редактирование текста и картинок (edit-01–03, 05–07, 49; edit-24 поиск и замена)

- **Инструмент «Редактировать PDF»:** клик по странице — рамки блоков (абзацев) из `ContentModel`; клик внутри блока — текстовый курсор, набор, `Backspace/Del`, выделение, `Ctrl+B/I/U`; панель FORMAT TEXT (шрифт из списка «в документе» и «системные» через DirectWrite, кегль, цвет, выравнивание, межстрочный и межбуквенный интервал, верхний/нижний индекс); «Добавить текст» — новый блок; перемещение/масштаб блока ручками; «Найти и заменить» (`Ctrl+H` занята режимом чтения — здесь `Ctrl+Shift+H`; замена по документу с предпросмотром); картинки (edit-05–07): выделение, перемещение, масштаб, поворот, отражение, обрезка (клип-путь), замена (из файла), «Редактировать в…» (внешняя программа по расширению → обратно по сохранению), добавить картинку (ADJUST OBJECTS).
- **Модель (`core/edit`):** `pdf_process_contents` со своим `pdf_processor` собирает операторы потока страницы в `ContentModel` (операторы как есть + текстовые объекты: глифы с позициями, шрифтами, `Tm`/`Td`/`TJ`), затем строки → абзацы (по интервалам и выравниванию) → блоки «редактируемые» и «только чтение» (с причиной: Type3, вертикальный, `/Pattern`, шрифт без `/ToUnicode` и без встроенного файла, текст в Form XObject за пределами поддержки); правка → перевёрстка абзаца (`Reflow`: перенос строк по ширине блока, кернинг по `advance` шрифта) → `Rewriter` пишет **только** изменённые текстовые объекты обратно (`pdf_new_buffer_processor`, `pdf_update_stream`), остальной поток байт в байт; `FontResolver` — четыре правила: 1) шрифт встроен полностью — используем; 2) подмножество без нужного глифа — расширяем из системного файла того же семейства (DirectWrite по имени, `fz_new_font_from_file`, новый `/FontFile2` с `pdf_add_cid_font`) и помечаем «подмножество расширено»; 3) системный шрифт есть, встроенного нет — встраиваем подмножество; 4) ничего нет — подмена на запасной (edit-49: настройка, по умолчанию Segoe UI/Times New Roman по засечкам) с честным сообщением. Картинки — `cm`-матрица XObject, обрезка — `W n` перед `Do`, замена — `pdf_add_image` + подмена в `/Resources/XObject`.
- **Стабильность** (метрика XL, этап 3): «пустая правка» (разобрать → записать без изменений) на корпусе `text-edit` (300 файлов: Word, LibreOffice, LaTeX, InDesign, сканы с OCR, кириллица) даёт рендер с `pixels == 0` отличий ≥ 90 % файлов; stext после правки содержит новое слово; `qpdf --check` = 0; undo байт в байт. Если < 90 % — сужается объём редактора (только TrueType/CID латиница и кириллица), не план.
- **Граничные случаи:** текст с `Tz`, `Tc`, `Tw`, `Ts` — поддержан; `TJ` с кернингом — пересчёт; текст в нескольких `BT/ET` одного абзаца — объединяется; блок на повёрнутой странице — редактирование в системе координат текста; документ с `/Perms` или подписанный — редактор отключён с объяснением; тегированный документ — после правки MCID сохраняются у изменённого блока (абзац целиком), новый блок — без тегов с предупреждением в отчёте доступности.
- **Acrobat:** отредактированный текст выделяется и ищется в Reader; встроенные подмножества корректны (`qpdf --check`, pypdfium2 рендер, `mutool draw -F txt`).

### 3.15 OCR и сканирование (ocr-01–09, 11, 12, 14; ocr-02 пресеты)

- **Распознать текст** (диалог): страницы (все/текущая/диапазон), языки (rus/eng/deu, несколько), режим «Searchable Image» (слой текста под картинкой — по умолчанию) / «Exact» (то же + «исправить перекос» растра не меняет исходную картинку) / «Editable text and images» — нет (Pro ClearScan), разрешение 300/600 dpi для растра распознавания, «Только страницы без текста», «Определить ориентацию»; полоса «Похоже на скан [Распознать]» при открытии (страница = одна картинка ≥ 90 % площади и нет текста); прогресс по страницам в строке состояния, отмена.
- **Движок (`core/ocr`):** `TessBaseAPI` из `libtesseract.lib` (Tesseract 5.5.2, LSTM, без OSD), `OcrPool` — 4 потока × свой `TessBaseAPI`, рендер страницы MuPDF при 300 dpi серым → `SetImage` → `ResultIterator` по словам (`RIL_WORD`: текст, bbox, `Confidence`); первый пункт сессии OCR — разобрать схему `fz_new_ocr_device`/rewrite-device в `source/fitz/ocr-device.c` и зафиксировать в журнале, почему слой пишем сами: **свой слой** — отдельный поток в `/Contents` с пометкой `/AcroBatyaOcr` (`BT 3 Tr /OcrFont 1 Tf … Tj ET`, ширины по `advance` под bbox слова, шрифт — встроенный TrueType с кириллицей для корректного копирования), исходный контент страницы не переписывается; «Исправить распознанный текст» (ocr-14) — панель слов с уверенностью < 60 (подозрения хранятся вне PDF в `state.sqlite`), правка перегенерирует только слой `/AcroBatyaOcr`; повторное распознавание удаляет старый слой; **ориентация** — перебор 4 поворотов на уменьшенной копии (150 dpi, первые 40 % высоты) по `MeanTextConf`, принимается, если лучший превосходит остальных ≥ 12 пунктов, иначе 0°; перекос — `fz_deskew_pixmap`/`pixDeskew` только для растра распознавания (в Exact — и для сохранения); **пакетное OCR** (ocr-09): папка/список → те же параметры → отчёт; «Скан → PDF» при сканировании — `fz_new_pdfocr_writer` не используем (тот же свой слой); tessdata — `TESSDATA_PREFIX` → `{app}\tessdata` (ASCII; при не-ASCII пути — `GetShortPathNameW`) → `C:\Tools\tessdata`; нет языка — предложение скачать (URL, sha256, 9,5 МБ) с разрешения; `WinOcrBackend` (Windows.Media.Ocr через WinRT) — запасной движок за флагом настроек, после 1.0 по качеству.
- **Сканирование** (ocr-01, 03, 04): `IScanSource` → `WiaScanSource` (WIA 2.0: `IWiaDevMgr2::EnumDeviceInfo`, `GetImageDlg` для диалога драйвера или свои параметры `WIA_IPS_XRES`, `WIA_IPA_DEPTH`, ADF/дуплекс через `WIA_DPS_DOCUMENT_HANDLING_SELECT`, `IWiaTransfer::Download` с колбэком прогресса; `S_FALSE` у `GetImageDlg` = отмена; `WIA_IPA_FORMAT` — `VT_CLSID`) и `FakeScanSource` (PNG из `tests/fixtures/scans/` или папки `OTTISK_FAKE_SCANNER=<папка>` — работает и в живом запуске без сканера); диалог «Сканер»: устройство, dpi (150/300/600), цвет/серый/ч-б, ADF, дуплекс, формат страницы, пресеты (ocr-02: JSON в настройках), «Распознать после сканирования», «Ещё страницы?» после листа; «Улучшить скан» (ocr-05, 06): deskew, выровнять фон (`pixBackgroundNormSimple`), descreen (низкочастотный), резкость (`pixUnsharpMasking`), адаптивное сжатие (бинаризация текста Sauvola → CCITT G4 + фон JPEG — упрощённый MRC), предпросмотр «было/стало»; «Улучшить фото» (ocr-07): `fz_detect_document` → `fz_warp_pixmap` (перспектива), затем те же фильтры.
- **Граничные случаи:** страница с текстом и картинкой — «только страницы без текста» пропускает; таблица без линий — слова по bbox, порядок чтения по строкам; язык не угадан (deu текст при rus+eng) — низкая уверенность → подсказка добавить язык; 600 dpi A3 — растр полосами, память ≤ 1,2 ГБ; сканер не подключён — список пуст, кнопка «Обновить».
- **Acrobat:** слой `3 Tr` — стандартный приём Acrobat «Searchable Image»; Reader ищет и выделяет; `qpdf --check` = 0.

## 4. Документная модель и данные

### 4.1 Контексты MuPDF, замки и потоки

```text
GUI-поток (QApplication, STA)                 │  DocumentSession — один QThread на документ
  MainWindow, PageView, панели, диалоги       │    владеет core::Document (fz_context документа)
  ↓ команды (lambda + QFuture)                │    все pdf_* правки, загрузка страниц, display lists,
  ↑ сигналы (QueuedConnection), QImage        │    stext, сохранение, журнал undo/redo, JS
                                              │    очередь задач с приоритетами; отмена через fz_cookie
RenderPool (QThreadPool, idealThreadCount-2)  │  CryptoWorker (поток на операцию подписи/проверки)
  QRunnable с thread_local fz_clone_context   │    OpenSSL, CNG; сеть — через HttpFetcher (sync над QNAM)
  fz_run_display_list(scissor = тайл)         │  OcrPool (QThreadPool 4, TessBaseAPI на поток)
  результат — QImage (implicitly shared)      │  QProcess: soffice.com, qpdf.exe, verapdf.bat; COM STA: Word, WIA
```

- `MuContext::global()` (`core/mu/context.h`): один `fz_context` на процесс (`fz_new_context(nullptr, &locks, FZ_STORE_DEFAULT)` = 256 МиБ), `fz_locks_context` **из трёх полей** (`user, lock, unlock` — так в MuPDF 1.28.5, `fitz/context.h:270`; пять полей в `tech-facts.md` — ошибка справочника) на `std::mutex[FZ_LOCK_MAX]`, `fz_register_document_handlers`; контексты документов и рендер-потоков — `fz_clone_context`; колбэки ошибок/предупреждений → spdlog, не бросают.
- **Одно правило — один поток на документ.** Всё, что трогает `pdf_document`/`fz_page`, идёт через `DocumentSession::post(Task) → QFuture<T>` или `edit(name, Task)`; display lists — единственное, что уходит в другие потоки. `PageHandle` держит `fz_page` только на время задачи (баги кеша при undo в 1.25/1.26); UI хранит `AnnotRef{page, objnum}`, `FieldRef`, `PageIndex` — не указатели MuPDF. Ни один `fz_*`/`pdf_*` указатель не покидает `core` + `DocumentSession`.
- **Отмена и приоритеты:** `fz_cookie` у каждой задачи рендера; при смене зума/прокрутки `PageView` ставит `abort=1` невидимым тайлам и поднимает приоритет видимым (`QThreadPool::start(r, priority)`).
- **Ошибки:** единственная точка входа в MuPDF — `mu::call(ctx, [&]{ … })` (`fz_try/fz_always/fz_catch`, в `fz_catch` — `fz_report_error` и бросок `MuError{fz_caught(ctx), fz_caught_message(ctx)}`); внутри лямбды нельзя `return`/`throw` и нельзя держать C++-объекты с деструкторами (longjmp), локалы, меняемые в try, — `fz_var`; страж `tools/fztry_guard.py` (ctest `unit.guard.fztry`): `fz_try(` только в `core/mu/error.h`, нет `return` внутри лямбд `mu::call`. Классы: `FZ_ERROR_FORMAT/SYNTAX` → «Файл повреждён» с «Открыть восстановленным», `FZ_ERROR_UNSUPPORTED` → «Не поддерживается», `FZ_ERROR_SYSTEM` (OOM) → документ закрывается, остальные вкладки живут; `MuError` на границе задачи превращается в `TaskFailed{code, message, hint}` → сигнал в UI. Внешние библиотеки (OpenSSL, libtiff, Tesseract) — свои RAII и `OsslError`/`TiffError`.
- **Память:** `FZ_STORE_DEFAULT` у контекста; `QCache<TileKey, QImage>` с cost = байты, лимит 384 МБ (настройка); display lists — LRU 40 страниц на документ, stext — LRU 16; `fz_shrink_store(ctx, 50)` при `QEvent::ApplicationDeactivate` и по таймеру простоя 60 с; растр > 64 МБ (печать 600 dpi) — полосами.

### 4.2 Открытие, страницы, многодокументность

- `fz_open_document_with_stream(ctx, fz_open_file_w(ctx, wpath))`; `OpenResult{ok, needsPassword, repaired, pdfa, signed, hasForm, hasXfa, error}`; пароль — `pdf_needs_password`/`pdf_authenticate_password`; `pdf_was_repaired` → полоса; права `/P` читаются один раз, `Document::allowed(Perm)`.
- **Раскладка знает только размеры** (`fz_bound_page` × N сразу при открытии — дёшево) и `/Rotate`; display list на страницу — `fz_new_display_list_from_page` (с аннотациями и виджетами); для печати «без пометок» — `fz_run_page_contents`.
- **Тайлы:** 512×512 device px, ключ `{doc, page, zoomBucket, dpr, rotation, tx, ty, layersHash, recolor, revision}`; zero-copy: `QImage(Format_ARGB32_Premultiplied)` + `fz_new_pixmap_with_data(ctx, fz_device_bgr(ctx), w, h, nullptr, 1, bytesPerLine, bits)` + `fz_clear_pixmap_with_value(0xff)` + `fz_new_draw_device` + `fz_run_display_list(…, scissor, &cookie)` + `fz_close_device` до `fz_drop_device` + `setDevicePixelRatio(dpr)`; превью 1/8 масштаба, пока тайлов нет; одна `fz_matrix ctm = scale(zoom·dpr) × rotate(view) × translate(−x0, −y0)` для рендера, хит-теста и выделения.
- `DocumentRegistry` держит `shared_ptr<Document>` по id вкладки; закрытие — после опустошения очереди задач; `RenderPool`/`TileCache` общие на процесс; один документ — одна вкладка; закрытие с правками — «Сохранить / Не сохранять / Отмена».

### 4.3 Журнал, undo/redo

- `pdf_enable_journal(doc)` при открытии PDF. Каждая правка — `Journal::Operation op(doc, "Название")` → `pdf_begin_operation` … `pdf_end_operation` (исключение → `pdf_abandon_operation`); вложенные операции MuPDF (`pdf_create_signature_widget` и т. п.) уже обёрнуты — begin внутрь begin не вкладывать. `Ctrl+Z`/`Ctrl+Y` → `pdf_undo`/`pdf_redo` в потоке документа; `UndoStack` — имена для меню «Отменить: записка» (`pdf_undoredo_state`/`pdf_undoredo_step`), группировка набора текста (операции с одним именем за 1 с сливаются), зеркало в `QUndoStack`.
- **В журнале:** аннотации, формы, страницы, редактирование контента, метаданные, закладки, ссылки, вложения, OCR-слой, оформление. **Не в журнале:** состояние вида, выделение, фильтры панелей, пароль (шифрование — отдельная операция «Сохранить как»). После undo/redo — `pdf_update_page` закешированных страниц, сброс display lists затронутых страниц (список страниц ведёт `Journal`), `revision++`.
- **Проверка покрытия (сессия 1.3, до редактора):** тест «журнал покрывает `pdf_update_stream`» (правка потока → `pdf_undo` → байты исходного потока) и «покрывает `pdf_add_image`/новые объекты»; если не покрывает — `Rewriter` и OCR-слой хранят прежний буфер и пишут обратно сами (решение фиксируется в `docs/progress.md` до этапа 3).
- **Операции с перезаписью** (объединение, уменьшение размера, OCR-растеризация «Exact», экспорт, Office-конвертация) создают **новый документ «Без имени»** во вкладке и не отменяются — диалог об этом говорит.

### 4.4 Сохранение (`Saver`)

Правила выбора режима: (1) `pdf_can_be_saved_incrementally` ∧ документ подписан (`pdf_count_signatures > 0`) → **только** `incremental`; «тяжёлая» правка на подписанном → `SaveError::WouldBreakSignatures` → отказ с объяснением и «Сохранить как копию»; (2) не подписан, правки лёгкие (аннотации, формы, метаданные, закладки, OCR-слой, оформление) → `incremental` по умолчанию (вопрос §12.6), полная — по «Сохранить как → Оптимизировать»; (3) удаление/вставка страниц, замена картинок, редактор текста, «уменьшить размер» → полная запись с `garbage=deduplicate, compress, compress-fonts, compress-images, objstms`; (4) смена шифрования, восстановленный файл (`pdf_was_repaired`), новый документ → полная. Запись — `pdf_save_document` через `fz_output` на `_wfopen` во временный файл рядом → `MoveFileExW(REPLACE_EXISTING)`; после сохранения документ переоткрывается в том же `DocumentSession` (чтобы `/ByteRange` и ревизии были верны). `do_linear` — никогда; линеаризация — `qpdf.exe --linearize` поверх (§3.17). «Сохранить как…» — диалог параметров (инкрементально/полностью, `objstms`, сжатие картинок, подмножества шрифтов, плоская копия, шифрование).

### 4.5 Автосохранение, восстановление, ревизии

- `Autosave` раз в 5 минут (настройка 1–30) при несохранённых правках: `pdf_save_journal` в `%LOCALAPPDATA%\AcroBatya\autosave\<sha256(path)>.journal` + копия исходного файла при первом автосохранении (`<sha256>.src.pdf`, если ≤ 500 МБ) и индекс `autosave/index.json` (путь, mtime, sha); документы, которые журналом не восстановить (восстановленные файлы), — целиком `<sha>.pdf`. При старте: найденные записи → диалог «Восстановить несохранённые изменения?» → `pdf_load_journal`; успешное «Сохранить» или «Не сохранять» удаляет запись. Тест: `taskkill /F` посреди правок → перезапуск → правки на месте.
- **Ревизии:** `pdf_count_versions`; «Просмотреть подписанную версию» — байты `[0, end_of_range)` подписи во временный файл → вкладка «только чтение»; `pdf_validate_change_history` — валидатору; список ревизий в свойствах подписи.

### 4.6 Подписи — граница MuPDF и нашего кода

MuPDF: виджет `/Sig` (`pdf_create_signature_widget`), плейсхолдер `/Contents` и `/ByteRange`, инкрементальная запись с патчем диапазонов, внешний вид (`pdf_signature_appearance_signed`), `pdf_signature_hash_bytes`/`pdf_signature_contents`, `pdf_validate_signature`/`pdf_validate_changes` как опора анализа изменений. Наше (§3.8): `AcroBatyaSigner : pdf_pkcs7_signer`, CMS CAdES-B через OpenSSL, TSA, патч `/V`, CNG-подписант, DSS/VRI и DocTimeStamp отдельными инкрементальными секциями, DocMDP/`/Perms`, валидатор, хранилище доверия, EUTL/AATL. MuPDF собирается **без** `HAVE_LIBCRYPTO`; `libpkcs7.lib` — заглушка.

## 5. Архитектура и технологии

### 5.1 Слои

`core` (чистый C++20, без Qt: MuPDF, OpenSSL, libtiff, Tesseract/Leptonica, fmt, spdlog, nlohmann-json, sqlite3; gtest без `QApplication`) → `services` (Qt Core + Gui + Network + PrintSupport без Widgets: потоки, настройки, процессы, сеть, COM, печать) → `ui` (Qt Widgets, `AcroBatya.exe`). ### 5.5 Сборка: конфигурации, CRT, PCH

- **Все цели — `/MD`** (`CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreadedDLL` во всех конфигурациях): Qt из aqt собран с `/MD`, vcpkg-триплет `-static-md-release` даёт `/MD`, MuPDF `Debug` пересобирается с принудительным `RuntimeLibrary=MultiThreadedDLL` **и снятым `_DEBUG`** через `tools/mupdf-build.ps1 -Config Debug` (`/p:ForceImportBeforeCppTargets=<abs>\ottisk-md.props` всем проектам; props: `<ItemDefinitionGroup><ClCompile><RuntimeLibrary>MultiThreadedDLL</RuntimeLibrary><UndefinePreprocessorDefinitions>_DEBUG;%(UndefinePreprocessorDefinitions)</UndefinePreprocessorDefinitions></ClCompile></ItemDefinitionGroup>`; `libmupdf.vcxproj` и `libtesseract.vcxproj` в Debug-группах явно задают `_DEBUG` и `MultiThreadedDebugDLL` — проверено; при `/MD` + `/D_DEBUG` CRT/STL выбирают `msvcprtd`/`ucrtd` и `_ITERATOR_DEBUG_LEVEL=2`, линковка с приложением даёт LNK2038 на C++-объектах harfbuzz/tesseract/zxing; `NDEBUG` не добавлять; проверка — `dumpbin /directives x64\Debug\libtesseract.lib x64\Debug\libmupdf.lib` без `MSVCRTD|ucrtd|msvcprtd|MDd_DynamicDebug`); `libresources.lib` — всегда из `x64\Release` (в `mupdf.sln` `Debug|x64` libresources отображена на `Release|x64`; это bin2coff-объекты без CRT и `/GL`); Qt в Debug-пресете — **release-DLL** (`CMAKE_MAP_IMPORTED_CONFIG_DEBUG=Release`), чтобы не тянуть `/MDd`-сборку Qt. Итог: `Debug` приложения = `/Od /Z7 /MD` с Debug-библиотеками MuPDF (без `/GL`, быстрая линковка) — цикл очереди; `Release` = `/O2 /Z7 /MD` с Release-библиотеками (`/GL`, LTCG, медленная линковка) — только рубежи, выпуски, 1.1 (`render_refs`) и 1.2 (`bench`); Release-цели — `AcroBatya render_refs render_tests bench`, остальные тесты — Debug; в этапе 0 линковка `render_refs` замеряется, при > 3 мин Release MuPDF один раз пересобирается `tools/mupdf-build.ps1 -Config Release -NoLtcg` (`WholeProgramOptimization=false`) и эталоны снимаются с неё; все замеры времени и памяти — Release; `asan` = Debug + `/fsanitize=address`; `fuzz` = + `/fsanitize=fuzzer`.
- **PCH + unity:** `target_precompile_headers` **на цель** (`<mupdf/fitz.h> <mupdf/pdf.h>` + std для `ottisk_core`; `<QtCore/QtCore>` для services; `<QtWidgets/QtWidgets>` для ui) — общего PCH нет, чтобы Qt не утёк в core мимо стража; `UNITY_BUILD ON`, батчи 12; `mocs_compilation.cpp` вне unity; `JOB_POOLS compile=10 link=2`; без ccache/sccache (решение 16).
- **Предупреждения:** `/W4 /permissive- /Zc:__cplusplus /utf-8`; для `core` и `services` — `set_target_properties(... PROPERTIES COMPILE_WARNING_AS_ERROR ON)` (CMake ≥ 3.24 → MSVC `/WX`; флага `-Werror` у `cl` нет); в `core/mu/call.h` `fz_try` обёрнут `#pragma warning(push)` / `disable: 4611` / `pop` — `setjmp` рядом с объектом с деструктором даёт C4611 и с `/WX` не собирается; чужие заголовки — Qt, MuPDF (`include`), Tesseract/Leptonica (`thirdparty/tesseract/include`, `thirdparty/leptonica/src`, `scripts/tesseract`) и `vcpkg_installed/<триплет>/include` — через `/external:I` + `/external:W0` (иначе `/W4 /WX` падает на C4200/C4201/C4100 в `baseapi.h`/`allheaders.h`, а не в нашем коде); исходники целей — `file(GLOB_RECURSE … CONFIGURE_DEPENDS)` по каталогам, новый файл в CMake не прописывается, `gtest_discover_tests` по exe.
- **Патчи MuPDF:** не планируются (security-11 — заглушка до ответа §12.1; сессию 7.7 с патчем чтения PubSec добавляет человек, см. «Правила работы» плана); если понадобятся — только `tools/mupdf-patches/` с пересборкой через `tools/mupdf-build.ps1` и строкой в журнал; `C:\src\mupdf` для очереди — только чтение.

### 5.6 Кодировки и пути

`/utf-8` у всех целей; `QT_NO_CAST_FROM_ASCII`; пути: `QString` в UI → `std::wstring` (`toStdWString`) → `fz_open_file_w` / `TIFFOpenW` / `_wfopen`; `std::filesystem::path` строится только из `std::wstring` или `u8string` (конструктор из `std::string` трактует байты в ACP 1252); `core/util/paths.h` — единственная точка конверсий и `toShortPath()` (`GetShortPathNameW`) для Tesseract и профиля LibreOffice; `.pfx` читается в память через `QFile`, не по пути; `QProcess` — `QStringList` (UTF-16), LibreOffice — `file:///` URL для `-env:UserInstallation`; `.ps1`/`.iss` — UTF-8 с BOM (тест `unit.guard.encoding`); Python — `PYTHONUTF8=1`, `-X utf8 -I` над скачанным; пролог скриптов очереди — `[Console]::OutputEncoding = UTF8; $OutputEncoding = UTF8; $PSDefaultParameterValues['*:Encoding']='utf8'; chcp 65001`; `cl.exe` по-русски — `msvc_deps_prefix` ставит CMake.

### 5.7 Интернационализация

Исходные строки — русские внутри `tr("…")` только в `ui`; `core`/`services` возвращают коды и английский текст журнала; `find_package(Qt6 … LinguistTools)` и новая сигнатура `qt_add_translations(TARGETS AcroBatya TS_FILES i18n/ottisk_ru.ts i18n/ottisk_en.ts MERGE_QT_TRANSLATIONS LUPDATE_OPTIONS -no-obsolete)` (позиционная форма `qt_add_translations(target TS_FILES …)` устарела); `update_translations` явно (сессия 9.2 — перевод агентами по частям `tools/ts_split.py`/`ts_merge.py`, один файл — один исполнитель), `release_translations` в сборке; язык — настройка + `--lang` (Системный/Русский/English, перезапуск); множественное число — `tr("%n стр.", nullptr, n)`; даты и числа — `QLocale`. ## 7. Безопасность

Что реально сделать без песочницы — и что делаем.

### 7.1 Пароли и права

Открытие с паролем — три попытки, пароль не пишется в журнал и настройки; «запомнить на время сессии» — только в памяти. Права `/P` соблюдаются всеми командами (§3.14), включая командную строку (`/p` при запрете печати — код 1 и запись в журнал). Пароли политик защиты — DPAPI (`CryptProtectData`, только текущий пользователь) по флажку (§12.5); пароли `.pfx` удостоверений — так же; экспорт удостоверения — только с вводом пароля. Шифрование записи — только AES (R4/R6); RC4 — чтение.

### 7.2 JavaScript

Выключен по умолчанию для всех файлов, кроме «доверенных папок и файлов» (Диспетчер доверия) и файлов, для которых человек нажал «Включить для этого файла» (запоминается в `state.sqlite` по sha256 первых 64 КБ + размеру). При выключенном JS: формы заполняются, вычисления/форматы не идут, жёлтая полоса. При включённом: MuJS с нашим `app`/`console`/`util`-подмножеством, без таймаута скрипта (механизма прерывания в MuJS/`pdf-js.c` 1.28.5 нет — JS только в потоке документа, UI не блокируется; «Известные ограничения»), без доступа к файловой системе, сети, запуска программ (`app.launchURL` → подтверждение внешней ссылки §7.4, `this.saveAs`/`mailDoc`/`print` без диалога — заглушки с записью), `app.alert` — модально, но с лимитом 3 подряд (security-36 «запрет тихой печати»).

### 7.3 Вложения и импорт

Вложения (`/EmbeddedFiles`, `/FileAttachment`) — только «Сохранить как…» для расширений из чёрного списка (`exe bat cmd com js jse vbs vbe ps1 msi msp scr pif reg hta jar lnk wsf wsh cpl inf`); остальные — «Открыть» через `ShellLauncher::openFile` (в тестах `FakeShellLauncher`; прямых `ShellExecute*` вне `services/shell_launcher.cpp` нет — страж `unit.boundaries`) из временной папки после подтверждения «Открыть вложение «x.docx» внешней программой?»; PDF-вложение — в новой вкладке в защищённом просмотре. Импорт FDF/XFDF/XDP/данных формы — подтверждение с именем файла и числом объектов (security-36); FDF с `/F` на другой документ — отказ.

### 7.4 Внешние ссылки и сеть

Любой переход по `/URI`, `app.launchURL`, `SubmitForm` на `http(s)` и загрузка веб-страницы — диалог «Открыть ссылку https://…? [Открыть] [Разрешить для сайта] [Запретить]» с памятью по хосту (Диспетчер доверия: списки разрешённых/запрещённых); `/Launch` — всегда запрещено; `/GoToR` — «Открыть файл …?». Сеть самой программы: TSA, OCSP/CRL, EUTL/AATL, загрузка tessdata, веб-страница → PDF, `SubmitForm` — всё через один `HttpFetcher` (QNAM над Schannel) с таймаутом 15 с, без редиректов на другой хост для OCSP/TSA, журнал URL без тела; выключатель «Сеть: разрешена / только подписи / выключена» в Установках → Защита; очередь в тестах — `FakeHttpFetcher` и локальные `tsa_serve.py`/`openssl ocsp` (живая сеть только с `OTTISK_LIVE_NET=1`). Никакой телеметрии, проверки обновлений нет (cloud-43 вне объёма).

### 7.5 Защищённый просмотр для чужих файлов (security-35 облегчённый)

Файл считается «чужим», если у него поток `Zone.Identifier` с `ZoneId ≥ 3` (скачан, из почты), или он лежит в `%TEMP%`/`Downloads`-вложениях почтовых клиентов, или открыт как вложение PDF. Тогда: только чтение (правки, сохранение, печать разрешены; формы — заполнение без сохранения до включения), JavaScript выключен, внешние ссылки и `SubmitForm` запрещены, вложения — только сохранить, жёлтая полоса «Защищённый просмотр: этот файл получен извне [Включить все функции]». «Включить» — снимает ограничения для файла (запись в `state.sqlite`), сам `Zone.Identifier` не трогаем. Это не песочница (security-34 вне объёма): защита от UB парсера — `fz_try` везде через `mu::call`, ASan-прогон и libFuzzer на `fz_open` на каждом рубеже (§9.5), ограничение памяти рендера (`FZ_STORE`, полосы), таймаут JS, `longPathAware`-манифест и проверка путей на `..`.

### 7.6 Что в программе никогда не делается

Не пишет в реестр ничего, кроме ProgID/Capabilities из установщика (страж `unit.guard.no_registry`: нет `QSettings::NativeFormat`); не хранит пароли открытым текстом; не отправляет данные без явного действия человека; не выполняет `/Launch`; не загружает код (плагинов нет); не повышает права (per-user установка, без UAC); не пишет в `C:\Program Files`, `HKLM`.

### 9.1 Структура тестов и метки ctest

```text
tests/unit/      gtest, метка unit, TIMEOUT 60, < 1 с каждый; данные — tests/data/mini/*.pdf (свои, ≤ 50 КБ) и fixtures
```

Имена `<слой>.<объект>.<свойство>` (`gtest_discover_tests(... TEST_PREFIX "engine." DISCOVERY_MODE PRE_TEST DISCOVERY_TIMEOUT 30)`). `ENVIRONMENT` у всех тестов: `QT_QPA_PLATFORM=offscreen;QT_QPA_FONTDIR=C:/Windows/Fonts;QT_FORCE_STDERR_LOGGING=1;OTTISK_DATA_DIR=<build>/test-data;PATH=<asan-bin>;$ENV{PATH}`. На каждом пункте плана: `ctest --test-dir build/debug -L "unit|ui" -LE slow -j 12 --timeout 60 --output-on-failure --no-tests=error` (или `-R <регекс>` рядом с правкой). В конце сессии — `tools/verify.py`. Рубеж — ещё `-L "render|engine|compat|e2e"`, ASan, фаззер 10 минут, `bench`, `build`.

**Покрытие объёма:** макрос `OT_FEATURE("view-10")` (`core/util/features.h`) в теле gtest-теста пишет ID в `RecordProperty("feature", …)` **и** печатает строку `OT_FEATURE:view-10` в stdout; в QTest — только строка в stdout. `ctest --output-junit` не переносит `RecordProperty` в XML, а `gtest_discover_tests` запускает каждый TEST отдельным процессом, поэтому `cmake/tests.cmake` задаёт `gtest_discover_tests(... XML_OUTPUT_DIR ${CMAKE_BINARY_DIR}/gtest-xml)` (CMake ≥ 3.18) и `tools/scope_report.py` на рубеже собирает `build/features-covered.json` из `<property name="feature">` в `gtest-xml/*.xml` и из `<system-out>` `ctest.xml`, печатает «закрыто N из M» по `docs/scope.json`; ID без теста — список в `docs/progress.md`; к Р5 — ≥ 95 % ID `full` с хотя бы одним тестом. Живой OCR не в `tests/unit/` (< 1 с) — `tests/engine/` с `engine;slow`, в `unit` — `FakeOcrBackend`.

**Что пишется «сначала тесты»:** вся логика без интерфейса — раскладка страниц, тайлы, формула буклета, поиск, FDF/XFDF, пароли, графт с outline, `ContentModel`, `FontResolver`, CMS, валидатор, DSS, автоопределение, автотеги, OCR-слой, колонтитулы; для XL — gtest-файлы с ожиданиями JSON на фикстурах до кода.
